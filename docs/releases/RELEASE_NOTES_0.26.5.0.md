# FreshAirIQ 0.26.5.0

Launch readiness for English-speaking users. Recommendations are unchanged (golden master: the only new value is the language marker `output_language: "de"`; German and English verified).

Fix (feedback FAIQ-FB-78614DD50929, 0.26.4.9: "eine Mischung aus Deutsch und Englisch im UI – die dynamischen Texte sind Englisch, die Überschriften Deutsch"): FreshAirIQ writes its recommendations in the Home Assistant server language (Settings → System → General), but the dashboard used the language of the user profile. With an English server and a German profile the headings were German and every recommendation English (and the other way round). The dashboard now always speaks the language of FreshAirIQ's own texts: the status and room entities carry `output_language` (`de`/`en`) and the card follows it, so one installation shows one language everywhere – dashboard, pushes, events, PDF. Every non-German server language gets English. Checked by rendering the real card with real English output in a browser: 0 German texts in 29 views (main card, details, every info panel, every room, every explanation, live updates, classic view); with a German profile on an English server the card is fully English.

English dashboard completed (same check, before the fix 33 German leftovers): last ventilation result (duration, reheating, start forecast, cross ventilation), room view ("Why?", Strategy IQ, Learning 3.0 shadow models, time-pattern samples, airflow factor, window names instead of entity IDs), learning panels (maturity, long-term learning, seasons), details (pollen off, trend, learning days), structure rooms, house banner, forecast explanations, classic view; texts shown after a click (PDF/export progress, feedback and support messages, error codes) and the card editor; the card picker description. Open views stay English during live updates (they reverted to German before). Learning diagnosis was half German in the backend ("Lernreife-Evidenz … Proben … Rest") and turned German again in the card – now English end to end. "kWh Strom/Gas" and the test notification ("Test successful …") are English on English servers. Mould list: rooms without climate sensors show "–" instead of "0 %".

Fix (found while simulating an English home for the screenshots): a room with two contacts where one contact is unavailable or missing (dead battery, removed device) stayed "open" forever after the other window was closed – the start-up guard kept every running airing open while any contact was unknown. The guard now holds for at most 15 minutes per contact (start-up, short radio drop-outs); after that the known contacts decide, so the airing ends and is logged. Because nobody knows whether the dead opening was open, such an airing is not used for learning (code FAIQ-CONTACT-UNKNOWN-001).

The German README has its own up-to-date German screenshots (`docs/screenshots/de/`). Full English automation guide (`docs/AUTOMATIONS.md`), English blueprints (`*_en.yaml`) and English examples.
