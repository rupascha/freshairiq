# FreshAirIQ 0.26.4.10

Support and community fix release on top of 0.26.4.9. Recommendations change only where described below (no close advice shortly after opening, exhaust-fan airings); everything else is identical in the golden master (6 scenarios / 117 cycles, German and English verified).

Fix (support case 472cf5b9, own installation: "alle Fenster geöffnet – er sagt mir direkt, dass ich wieder schließen soll, obwohl die 15-Minuten-Prognose noch viel Potenzial zeigt; die Empfehlung kam nach ca. 10 ml"): with eleven rooms open the house forecast promised about 290 ml in 15 minutes, but every room on its own was below its small-room 5-minute threshold, so each room said "Close", the house accepted the unanimous room closes and the live coach shortened the session – all within 3.5 minutes. New rule: until the airing time FreshAirIQ showed when the window was opened (frozen per room at session start) has passed, a close is only advised when moisture would come in (net 5-minute effect negative or the outside/reference air no longer drier), plus the unchanged hard limits (maximum duration, protection limits). Room model, floor/house aggregate and live coach follow the same rule (one shared definition of "moisture would come in"); the minimum airing time still applies; the shown target is never shorter than the time shown at opening. A window opened while others are already aired joins that airing (its planned time is what is left of it, or a fresh airing time if that airing is already over), so all windows end together; a window opened during a fan-only airing gets its planned time from that moment. The house/floor target is the one frozen for the earliest opened window – not the duration recalculated every cycle. Golden master: in three scenarios sessions that were closed after 3–4 minutes with 20–56 ml still expected in the next 5 minutes now run to the planned time; all other cycles identical (German and English verified).

Fix (community post, photo "Garage schließen" while only the exhaust fan runs): a room aired only by its exhaust fan was treated like an open window – after the 20-minute window maximum (or a small return) FreshAirIQ said "Garage schließen", permanently while the fan kept running, and showed "Schutzregel hat Vorrang". A running fan is now only stopped when moisture would come in, and the advice says what to do: "Lüfter in Garage ausschalten" (push: "Die Außenluft ist gerade feuchter als die Raumluft. Lüfter ausschalten."; event label "Bitte Lüfter ausschalten"; while it helps: "Lüfter in Garage laufen lassen"). Mixed cases read "Bad schließen · Lüfter in Garage ausschalten" – a running fan is only named when that room itself should stop, a fan never shortens or ends the planned time of open windows, and "noch ca. X min" is no longer shown for a fan alone. The push says "…gerade feuchter…" only when the outside air really is more humid, otherwise "Die Außenluft ist kaum noch trockener als die Raumluft. Lüfter ausschalten." The dashboard recognises a fan airing also right after the fan switched off.

New (to-do "Feedback alle 15min"): feedback can be sent once every 15 minutes (spam protection). The support view says so, shows "Noch X Min. gesperrt" on the button and the remaining time after sending; Diagnostics Hub 0.3.3.86 enforces the same limit (HTTP 429), and the integration shows the Hub's remaining time too.

Clean-up: unused code removed (old Nacht/Pollen/Lernen tile styles, four unused card helpers/tables, an unused coordinator method, unused imports and floor constants, two unused local variables in the learning maturity code, unused imports in the release tools); a test that loaded `language_confidence.py` outside the package now imports it normally.

- New tests: `tests/test_planned_airing_026410.py`, `tests/test_feedback_cooldown_026410.py`.
