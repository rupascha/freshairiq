# FreshAirIQ 0.26.4.3

- One settings surface: FreshAirIQ is now configured only under Settings → Devices & services → FreshAirIQ → Configure. The dashboard settings centre (room, resident, level, threshold and notification editors) and its write API (`/api/freshairiq/settings/…`) were removed, so there is no second code path that can change the configuration. The details window no longer shows the settings gear from 0.26.4.2; the threshold detail and the support panel are read-only and name where to change things. Feedback still goes through its own endpoint (`feedback_api.py`).
- Diagnostics consent hint: the card no longer writes the consent itself. Admins see "Diagnosen teilen?" with "Öffnen" (goes to the integration page in Devices & services) and "Später" (hides the hint for seven days in this browser).
- New: unexpected exceptions in the config, options and room dialogs (shown by Home Assistant only as "Unknown error occurred") are logged with the error code `FAIQ-CONFIG-FLOW-001`, stored in the local diagnostics with exception type and code location only (no message, no input, no entity IDs) and — only with diagnostics consent and reporting not switched off — sent to the Diagnostics Hub. Home Assistant's own flow-control exceptions (abort etc.) are not reported. This would have surfaced GitHub #12 from the first occurrence.
- Fix (measurement): "wait"/"pollen wait" recommendations mean "keep the windows closed", but an episode only counted as followed when a ventilation session started — the opposite. Hub data showed 1,739 "missed" of 1,807 recommendations. Keeping the windows closed now counts as followed, opening them as not followed; response-time learning only uses active ventilation advice.
- New (measurement): each recommendation episode records whether a push message was actually delivered. The beta funnel now reports `recommendation_notified`, `recommendation_followed_notified` and whether notifications are configured at all, so "ignored" can be told apart from "never reached the resident".
- Support case analysed (support-f6e1892b, 0.26.2.8, "Raum Symbol wirft Fehler"): the configuration changed at 17:49 (the room edit was saved), and the error came from the next dialog step for the room's window contact — the `include_back` NameError from GitHub #12, fixed since 0.26.2.13.
- Removed dead code: `option_relationship_message_de` (only used by the removed settings API). 57 tests that only checked the dashboard settings were retired or reduced to their Devices & services part; two new test files cover the single settings surface and the flow-error/follow-rate changes.

## Known limits
- Tested in Chromium, with the coordinator golden master and unit tests; not yet on a real Home Assistant instance.
- Dashboards that pointed users to the in-card settings now need Devices & services.
